# Tests

## Test 1 - Show worker run outcomes and duration analytics [sanity]
Viewport: desktop
Covers: Performance workspace, GET performance route family, Worker summary, run success/failure rates, run durations
Description: Verifies completed and failed managed Runs become visible operational metrics without creating a worker score.

Setup:
1. Create one managed Worker and produce at least one COMPLETED Run and one FAILED Run for that Worker through the existing Jobs/Runtime workflow

Steps:
1. Open Performance
2. Inspect the top metrics and Worker summary row
3. Refresh the page

Expected: The Worker remains visible with the same Run counts, success/failure percentages and duration values after refresh, and the page states that no employee quality score is used.

## Test 7 - Fence stale workers and dead-letter repeated expiry
Viewport: backend

## Test 8 - Hold and replay a GitHub issue write

Expected: The first request is HELD with the exact normalized payload visible in the Action and Approval records; the changed replay is rejected with conflict; approval revalidates the credential and executes only the original payload.

## Test 31 - Permanently delete active Jobs and Workers
Viewport: desktop
Covers: DELETE job route family, DELETE worker route family, active Run force-cancellation, Work Item purge, trigger/dependency cleanup, automatic Agent credential revocation
Description: Verifies Delete means delete even when work is currently running or waiting for approval.

Setup:
1. Create an automatically provisioned Worker with two Jobs, including one recurring Job, and enough organization Work Item history to exceed 200 records; start work so at least one Work Item is RUNNING or WAITING_APPROVAL

Steps:
1. Delete the active Job and confirm without waiting for its Work Item to finish
2. Confirm the Job disappears from Jobs and its Work Items disappear from Work Queue
3. Delete the Worker while its remaining Job has active work, then inspect Workforce, Jobs, Triggers and Connections → Agent identities

Expected: Neither destructive action is blocked by active work or by Work Item pagination beyond 200 records; the UI automatically continues bounded deletion batches, associated Runs are CANCELLED, Job/Worker definitions and all associated Work Items/triggers are removed, dependency references cannot recreate the deleted Job, historical Run/Audit records remain for traceability, and the automatically provisioned Agent Identity is DISABLED with its credential REVOKED.
