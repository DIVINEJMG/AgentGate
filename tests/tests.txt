# Tests

## Test 1 - Connect Gmail and read recent messages only through AgentGate [sanity]
Viewport: desktop
Covers: credential-backed provider connect route, Gmail fixed-origin adapter, capability catalog, Action Gateway execution
Description: Verifies a Gmail token is encrypted after validation and a bounded recent-message read still requires AgentGate authorization.

Setup:
1. Configure the AgentGate integration vault and use a dedicated Gmail test account access token with Gmail read-only access
2. Create an active Worker/Agent and an ALLOW policy for `gmail.messages.recent.read`

Steps:
1. Open Integrations → Gmail, submit the test access token, and confirm the mailbox connection
2. Grant the Agent the live `gmail.messages.recent.read` capability and execute that exact scope through the Action test surface
3. Refresh Integrations and Actions

Expected: Gmail remains CONNECTED with only an encrypted credential fingerprint visible, the Action is EXECUTED through the Action Gateway, and at most five recent message metadata/snippet records are returned without exposing the token.

## Test 2 - Drive and Calendar expose bounded read-only workplace capabilities
Viewport: desktop
Covers: Google Drive adapter, Google Calendar adapter, provider health checks, fixed official API origins
Description: Verifies separate Google provider connections expose only their declared bounded read operations.

Setup:
1. Configure the integration vault and use dedicated Google test access tokens with Drive metadata-read and Calendar read access

Steps:
1. Connect Google Drive and Google Calendar from the provider catalog
2. Check health on both connections
3. Inspect PROVIDER OPERATIONS on each connection

Expected: Both connections are healthy, Drive exposes profile/recent-file reads, Calendar exposes primary/upcoming-event reads, and neither connection exposes send/create/write operations.

## Test 3 - Slack capability remains subject to policy and approval
Viewport: desktop
Covers: Slack auth.test validation, Slack conversations.list adapter, Action Gateway policy and approval boundary
Description: Verifies adding Slack does not let the provider adapter bypass REQUIRE_APPROVAL.

Setup:
1. Connect a dedicated Slack test token with channel-read access
2. Grant an Agent `slack.channels.read` and create a REQUIRE_APPROVAL policy for that scope

Steps:
1. Request `slack.channels.read` through the Action test surface
2. Confirm the Action is HELD and approve it from Approvals
3. Return to Actions

Expected: Slack is not called before approval; after reauthorization the same held Action executes and returns only the bounded channel list.

## Test 4 - Credential-backed providers and Generic REST/MCP fail closed without safe prerequisites
Viewport: desktop
Covers: integration vault guardrail, Generic REST/MCP egress guard, no arbitrary URL execution
Description: Verifies F18 does not weaken credential storage or create an SSRF-style generic connector.

Steps:
1. With no `INTEGRATION_MASTER_KEY` configured, open Gmail, Drive, Slack and Calendar cards
2. Inspect the Generic REST / MCP card
3. Attempt no GitHub token and connect a public GitHub repository

Expected: Credential-backed workplace providers show VAULT REQUIRED and cannot submit credentials, Generic REST / MCP shows GUARDED with no connect action, while public GitHub remains connectable without weakening either guard.

## Test 5 - Inspect the expanded provider catalog through API v2 on mobile
Viewport: mobile
Covers: v2 integration normalization, responsive multi-provider catalog, provider-specific metadata rendering
Description: Verifies the expanded integration model remains usable on a phone-sized viewport.

Setup:
1. Have at least one GitHub connection and, when the vault is configured, one credential-backed workplace connection

Steps:
1. Open mobile navigation → Integrations and switch to API v2
2. Scroll the provider catalog and select each existing connection
3. Inspect provider name, credential posture, health and provider operations

Expected: GitHub, Gmail, Google Drive, Slack, Google Calendar and guarded Generic REST/MCP cards render without horizontal clipping; connection details use provider-specific names/metadata and continue to label provider operations as NOT AGENT PERMISSIONS.
